# RAG 模块设计：检索增强的翻译记忆与一致性（第一阶段收尾 / 展望落地）

> 定位：不新增独立系统，而是把现有 L1–L4 记忆体系**检索化、语义化**，
> 直击两个已实证的失败模式：术语/译法跨块不一致（复核清单 P1-1 的论据）、
> 低资源方向缺乏领域示范。

## 1. 三个落点（按价值排序）

### R1 翻译记忆检索（TM-RAG）——主模块
推理时对每个句块，从平行语料 + 历史译文（L2 SQLite 已有句对）检索 top-k 相似
源句及其译文，作为 few-shot 示例注入 prompt：

```
[检索] source chunk → 混合检索（BM25 + 向量）→ top-3 (src, ref_translation)
[注入] prompt = 系统指令 + 术语表 + "参考相似句对：" + top-3 + 待译句
```

价值：领域适应（测试分布外句子获得领域示范）+ 术语一致性（示范句携带术语
正确用法）。低资源缅向预期收益最大。

**已知风险（必须诚实）**：SFT 训练时 prompt 无示例段，推理时注入构成分布偏移。
对策两条：v0 先做推理侧消融验证收益；v1 做 RAG 增强训练（SFT 数据构造时随机
注入检索示例，训练推理分布对齐——即检索增强微调的标准做法）。

### R2 术语检索语义化——升级 L3
现状：GlossaryMemory.retrieve 为精确命中（词面匹配），长尾术语变体召回不到。
升级：术语条目嵌入索引（多语 bge-m3），检索改为"精确命中优先 + 语义近邻补充"，
top-k 截断防噪声。工程量小（术语库仅数百条），收益直接体现在术语命中率指标。

### R3 跨块一致性检索——直击译法冲突
文档翻译到第 N 块时，检索前 N-1 块中**共享术语/短语的已定译法**注入约束：

```
[触发] audit 检出本块含已出现术语 → 检索其历史译法
[注入] "前文译法（必须保持一致）：pipeline parallelism → 流水线并行（块3）"
```

这是纯文档级机制——单看任何一块译文都正确、冲突只在跨块出现，句级模型与
句级奖励在原理上无法覆盖，正是 episode 级奖励的动机。R3 让该失败模式先有一个
非训练的工程解，再与 agentic RL v1 汇合（检索命中→审计→重试的观测空间扩大）。

## 2. 技术选型（沿用项目零重依赖哲学）

| 组件 | 选型 | 理由 |
|---|---|---|
| 嵌入模型 | BGE-M3（多语，含缅甸语支持） | 单模型覆盖 my/zh/en；本地推理；hf-mirror 可下 |
| 向量索引 | SQLite 表 + numpy 余弦 | 10⁴–10⁵ 规模足够；不引入 FAISS/Milvus |
| 稀疏检索 | 字符级 BM25（zh/my 天然适配） | 缅文无分词，字符级是正解；与 chrF 同哲学 |
| 融合 | RRF（倒数排序融合）+ top-k 截断 | 简单可解释，答辩好讲 |

## 3. 评测协议（对齐已有指标）

- 消融四组：无 RAG / R1 / R1+R2 / R1+R2+R3（同模型同解码）
- 主指标：chrF++、COMET、**术语命中率**、**译法冲突数**（audit_document 直接产出，
  R3 的核心证据指标）、prompt 长度开销
- 方向优先级：zh→my（headroom 最大，与全量后训练同判据）

## 4. 实施分期

| 期 | 内容 | 量 |
|---|---|---|
| v0（2–3 天） | R2 语义术语检索 + R1 推理侧消融（用现有 eval_pilot 跑 on/off） | 全部组件现成 |
| v1（1 周） | R3 跨块一致性 + RAG 增强训练数据构造（对齐分布） | 依赖 v0 结论 |
| v2 | R1/R3 检索命中作为 agentic RL 的观测特征进入轨迹 | 与 agentic v1 汇合 |

## 5. 与后训练/RL 的关系（答辩串词）

> "RAG 与后训练不是替代关系：RAG 在推理时提供外部证据（示范句/历史译法），
> 后训练改变策略本身。检索命中的反馈（术语是否被采纳）天然构成 agentic RL
> 的奖励分量——检索、审计、重试在 v2 汇合成同一个轨迹环境。"
