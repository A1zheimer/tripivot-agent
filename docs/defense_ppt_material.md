## P4 SFT 方案

要点：
- 基座 Qwen2.5-7B-Instruct + LoRA（r=16 / α=32，40M 可训练参数 = 全参数的 0.53%）

- 单张 A800-80G，实际 **~11 小时**

## P6 后训练问题定义

要点：
- SFT 的局限：只在旧分布参考译文上极大似然，存在 exposure bias
- 两条改进路线（本项目要回答的问题）：
  - **OPD**：学生在线采样 → 教师逐步 logits → 反向 KL（稠密信号，受教师上限约束）
  - **GRPO**：组采样 → 指标奖励（chrF/格式）→ 组内标准化策略梯度（稀疏信号，可超教师）
- 公式：L_OPD = 0.6·KL(π_s‖π_t) + 0.4·NLL；GRPO 奖励 = 0.75·chrF + 0.25·格式 − 长度惩罚
配图：两条路线对比示意（左：教师→学生蒸馏；右：采样→奖励→更新循环）

## P7 对比实验设计（公平性三保证）

要点：
- 同一 SFT 合并基座（checkpoint-10772 merge）初始化
- 同一数据分布、同一 held-out（400 条/方向，贪心解码）
- 独立 adapter / 独立评测门 / 独立产物，可回滚可消融
配图：双分支对照实验流程图（本文件§1 的 ASCII 图美化版）

## P8 OPD 分支实现

要点：
- chunked on-policy：每 chunk 合并当前 adapter → vLLM 采样 k=4（T=0.7）→ 教师同词表逐步 KL → 更新
- 教师 Qwen2.5-14B（同 tokenizer 是逐步蒸馏的硬约束，32B 留给全量版）
- ~750 步，lr 5e-6（SFT 的 1/20）
讲稿：为什么 chunked——严格逐步 on-policy 与 vLLM 引擎冲突，块级近似是 GKD 论文的标准实践

## P9 GRPO 分支实现

要点：
- 每 prompt 组采样 G=8（T=1.0），奖励 = 0.75·chrF++ + 0.25·格式完整 − 长度惩罚
- 组内标准化优势 A=(r−μ)/(σ+ε)，KL 锚 β=0.02 防坍缩
- 奖励全部本地计算（COMET 受限下载，工程折中并保证两分支同尺）
- ~250 更新步，lr 1e-6

## P10 试点结果：OPD vs GRPO（2026-09-08 实测，en-zh，252 条 held-out）

| 指标 | baseline(SFT) | OPD-R1 | GRPO-R1 |
|---|---|---|---|
| COMET | 0.7921 | **0.7984** | 0.7927 |
| BLEU | 0.0493 | 0.0212 | **0.0627** |
| chrF++ | 0.2579 | 0.2581 | **0.2622** |
| 长度比 | 1.32 | 0.737 | 1.223 |
| 退化率 | 3.57% | **0.00%** | 3.17% |

讲稿主线（按实测结果定稿）：
- **GRPO 综合最优**："指标奖励直接优化目标——BLEU +27%、chrF 最高、长度健康，
  且 KL 锚全程 <0.001 证明 RL 过程高度稳定（无奖励黑客迹象）"
- **OPD 单句质量最优但暴露蒸馏副作用**："COMET 最高、退化清零，但教师简洁风格
  经反向 KL 传递导致欠译（长度 0.74）——稠密信号的效率与风格迁移的双刃剑"
- **方法选型结论**："忠实覆盖优先选 GRPO；流畅无误优先选 OPD；两者可组合
  （OPD 塑形 → GRPO 对齐指标）作为后续方向"
- 加分点：训练曲线讲头——OPD 的 KL 从 2.16 震荡收敛至 0.33（单样本打印的
  噪声判读），GRPO 的奖励平滑爬升至 0.418

## P12 工程问题全记录（精选 5 个）

| 现象 | 根因 | 解决 |
|---|---|---|
| 集群域名全 NXDOMAIN | EasyConnect 不推送校园 DNS | 挖日志找内部 DNS，IP 直连 |
| 作业 2 秒失败 | Slurm 从 spool 副本执行，$0 失效 | SLURM_SUBMIT_DIR |
| cuda available: False | PyPI 最新 torch 是 cu130，驱动只到 12.8 | 钉 torch 2.7 cu126 |
| vLLM 引擎起不来 | V1 引擎与父进程 CUDA 冲突 | VLLM_USE_V1=0 |
| 模型加载 TypeError | transformers 5.x 移除 warmup_ratio | 钉 4.51.1 |
讲稿：抽象教训——版本钉死>最新版；长链路必须容错+幂等；执行服务端化
