> 单位：港科大（广州）· HPC2 智算平台实验
> 关联材料：`docs/`（结论、设计文档、工程报告）、`artifacts/`（评测明细与训练日志）、

## 摘要

本项目面向缅甸语/中文/英语三语文档翻译，构建了从数据管线、LoRA 微调、后训练方法
对比到轨迹级强化学习探索的完整训练体系，并沉淀了可在饱和 GPU 集群上全自治运行的
自动化训练工程。核心结果：(1) SFT 微调在低资源缅向取得大幅提升（zh→my COMET
+42%、BLEU +76%；my→zh chrF +62%），同时暴露高资源方向容量竞争问题；(2) OPD
（教师在线蒸馏）与 GRPO（指标奖励策略梯度）的对照试点表明：试点规模下两者与基线
均无统计显著差异，但行为特征差异稳健（OPD 单句质量最优且退化清零、代价是欠译；
GRPO 忠实覆盖最优且 RL 过程高度稳定）；(3) 轨迹级 RL v0 与文档级审计对照实验
验证了机制可行性并给出环境校准的下一步设计依据。

## 1. 背景与挑战

- **任务**：my↔zh、en↔zh 文档级翻译，落脚点为具备规划-检索-翻译-审计-修订-记忆
  循环的翻译智能体
- **挑战一（数据）**：缅甸语低资源，平行语料稀缺且噪声高（ALT 语料存在对齐失败
  样本，见 §10 问题记录）
- **挑战二（方法）**：后训练路线（稠密教师信号 vs 稀疏指标奖励）缺少面向本任务的
  实证对比
- **挑战三（工程）**：目标集群 GPU 长期饱和（实测 14 小时零调度流转）、环境异构
  （驱动/依赖版本碎片化）、校园 VPN 不稳定

## 2. 数据管线

- ALT 平行语料（NICT，CC BY 4.0）+ 中文维基三领域（科技/国际/财经）各 1 万条单语，
  经 NLLB/opus-mt 蒸馏为平行对
- 准入规则：NFC 归一化、脚本比例、长度比、重复句对去重、高置信 Zawgyi 拒绝
- 防泄漏：双语数据按中文枢纽句哈希切分 train/val/test，杜绝三语对齐后跨集泄漏
- 术语体系：silver/safe/gold/curated 四层，训练采用 18 条人工术语
- 训练集：**91,852 条**（4 语向 × 3 领域）

## 3. SFT 微调

- 基座 Qwen2.5-7B-Instruct + LoRA（r=16/α=32，40M 可训练参数，gate/o/v/up/down
  全目标），术语软约束 prompt（与推理同构）
- effective batch 16，lr 1e-4，2 epochs = **10,772 步**，单卡 A800 约 11 小时
- 收敛曲线见 `docs/assets/sft_loss.png`（538 个真实 loss 点）

**效果（vs 原版 Qwen，252/249 条 held-out，贪心解码；BLEU 按目标语选择分词器：
zh→`zh`、my→字符级近似）**：

| 方向 | COMET | BLEU | chrF++ |
|---|---|---|---|
| zh→my | **+42%**（0.445→0.631） | **+76%**（0.244→0.430） | **+81%**（0.187→0.339） |
| my→zh | +11% | **+80%**（0.092→0.165） | **+62%**（0.113→0.184） |
| zh→en | −5% | +16%（0.183→0.213） | +6% |
| en→zh | ≈0 | +8%（0.229→0.248） | +7% |

- 原版 Qwen 中译缅 **55% 输出退化文本**，微调后降至 37%
- **发现：四方向共享单一 LoRA 存在容量竞争**——低资源方向大幅获益的同时 zh→en
  回退（COMET −5%、退化率 11%→22%）；改进方向为分方向 adapter / 语向重采样

## 4. 后训练对比实验（OPD vs GRPO）

### 4.1 设计

同一 SFT 合并基座、同数据分布、同 held-out（en-zh，252 条）双分支平行对照：

- **OPD-R1**（教师在线蒸馏）：学生 chunked on-policy 采样（vLLM 子进程隔离）→
  Qwen2.5-14B 同词表教师逐步 logits → 损失 `0.6·反向KL + 0.4·NLL(ref)`，
  lr 5e-6，750 步
- **GRPO-R1**（指标奖励策略梯度）：组采样 G=8（T=1.0），奖励 `0.75·chrF++ +
  0.25·格式完整 − 长度惩罚`，组内标准化优势 + KL 锚（β=0.02），lr 1e-6，500 步
- 方法学定位：GRPO 为单步策略梯度（contextual bandit 范畴）；OPD 为教师蒸馏
  （非 RL）——对比实质是"稠密教师信号 vs 稀疏指标信号"

### 4.2 结果

| 指标 | baseline(SFT) | OPD-R1 | GRPO-R1 |
|---|---|---|---|
| COMET(wmt22-comet-da) | 0.7921 | **0.7984** | 0.7927 |
| BLEU(zh) | 0.2478 | 0.2582 | **0.2603** |
| chrF++（逐句均值） | 0.2579 | 0.2581 | **0.2622** |
| 长度比 | 1.320 | 0.737 | 1.223 |
| 退化率 | 3.57% | **0.00%** | 3.17% |

**显著性**：配对 bootstrap（1000 次重采样），所有两两对比 p > 0.46，均不显著
（`artifacts/eval/significance.json`）。

**结论**：
- 试点规模下方法间无统计显著差异；**稳健发现是行为特征**——OPD 的长度坍缩
  （0.737）+ 退化清零符合反向 KL 的 mode-seeking 与教师风格迁移预期；GRPO 长度
  健康、chrF/BLEU 均为最优
- 空结果机理：en→zh 恰为 SFT 增益最小方向（句级空间近饱和、headroom 最小）；
  全量版应优先 zh→my
- 训练动态：OPD 的 KL 2.16→0.33、NLL 3.09→1.4（单样本打印含噪声，滑窗趋势
  双降）；GRPO 块均奖励 0.416→0.418（第一块训练后的 on-policy 提升）、KL 锚
  全程 <0.001（无奖励黑客迹象）。曲线见 `docs/assets/`

## 5. 轨迹级 RL v0（agentic 方向验证）

将仓库审计-重试循环作为 RL 环境的首次实跑：初译采样 → 结构化审计反馈（缺术语/
退化/过短）→ 条件重译 → 终态奖励（chrF+术语+格式−重试惩罚）→ 全轨迹 token 策略
梯度 + KL 锚。

- 结果：800 步一次跑通，KL 锚 ~0.0007
- **核心发现：审计触发率仅 0.4%**（3/800）——SFT 策略在简单审计下很少产生硬伤，
  轨迹退化为单轮。结论：**审计标准必须校准到"重译是真实决策"**（v1 引入 chrF
  阈值/术语精确匹配等软触发）。完整设计见 `docs/agentic_rl_design.md`

## 6. 文档级 Agent 证据

同一篇 19 块技术文档、同一审计标准的 A/B 对照：

| 组 | 模型 | 审计不通过率 |
|---|---|---|
| A | 原版 Qwen + Agent 机制 | **52.6%**（10/19） |
| B | SFT LoRA + Agent 机制 | **5.3%**（1/19） |

SFT 训练使 Agent 审计一次通过率从 47% 提升至 95%（**10 倍**）——"训练服务于
Agent 生态位"的直接文档级证据。术语跨块一致性指标因度量缺陷（中文输出中检索
英文术语的启发式不成立）如实弃用，B vs C（Agent 机制净贡献）列为后续工作。

## 7. 训练工程体系

- **多队列竞速 + 自动降级**：同一作业在 emergency/A40/long_gpu 多队列分身，
  总裁判先到先得；75 分钟无卡自动降级单卡——在 14h 零流转的饱和集群上完成全部
  训练（累计 30+ 作业调度）
- **服务端全自治**：训练、编排、上传全部 nohup 守护，客户端仅观察——项目期间
  VPN 断连 8+ 次、登录 VIP 轮换 4 次，训练零中断
- **环境版本钉死**：torch 2.7.1+cu126 / transformers 4.51.1 / vllm 0.9.2 /
  tokenizers 0.21.4 / peft 0.14.0（兼容矩阵经实测标定）
- **演示系统**：本地 Web 界面（文档上传模拟解析 → 流水线可视化 → 最终方案呈现），
  缓存真实译文回放，三语向案例经人工通读 + 字符级重复检测双门槛校验

## 9. 局限与后续

1. 后训练对比为 en-zh 试点（n=252，headroom 最小方向），四方向全量在路线图
2. RL 作用于句级翻译策略；Agent 的规划/修订决策仍为规则驱动——agentic RL
   （episode 级奖励 + 跨步信用分配）为下一步，其必要性由译法冲突这一纯文档级
   失败模式驱动（单看任一 chunk 正确、冲突只在跨 chunk 出现，句级奖励原理上
   无法覆盖）
3. 奖励采用 chrF 而非 COMET（模型获取约束；两分支同尺公平不受影响）
4. zh→my 参考来自蒸馏，指标上限受参考质量约束；缅文 BLEU 为字符级近似
5. 方向间容量竞争（zh→en 回退）待分方向 adapter 解决

## 10. 工程问题全记录（节选）

| 现象 | 根因 | 解决 |
|---|---|---|
| 集群域名全 NXDOMAIN | EasyConnect 不推送校园 DNS | 解析客户端日志定位内部 DNS，SSH 改 IP 直连 |
| sbatch 作业 2 秒失败 | Slurm 自 spool 副本执行，$0 非仓库路径 | `SLURM_SUBMIT_DIR` |
| 模型下载 401 | HF xet CDN 绕过镜像 | `HF_HUB_DISABLE_XET=1` |
| cuda available: False | PyPI 最新 torch 为 cu130，驱动仅支持 ≤12.8 | 钉 torch 2.7.1(cu126) |
| TrainingArguments 报错 | transformers 5.x 移除 warmup_ratio | 钉 4.51.1 |
| vLLM 引擎崩溃 | V1 引擎与父进程已初始化 CUDA 冲突 | `VLLM_USE_V1=0` |
| 块间采样 OOM | 训练进程缓存显存未归还 | 采样子进程隔离 + gc/empty_cache |
| BLEU 数值异常 | sacrebleu 默认 13a 不切分中缅文 | 按目标语选择分词器并重算 |
| 演示案例出现乱码 | ALT 对齐失败样本未被人工审读 | 人工精选 + 字符级重复检测双门槛 |

**方法论教训**：异构集群上版本钉死优先于追新；长链路自动化必须逐步容错 + 幂等；
执行全部服务端化，客户端只做观察；演示数据必须人工通读。
